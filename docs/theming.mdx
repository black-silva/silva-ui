# Theming

Silva UI components read CSS variables from the nearest theme scope. Use a built-in `Theme`, or compile a custom variable class with Vanilla Extract.

## Built-in themes

```tsx
import { Box, Text, Theme } from "silva-ui"

<Theme name="dark">
  <Box bg="card" color="primary" p="large" borderRadius="large">
    <Text>Dark themed content</Text>
  </Box>
</Theme>
```

Available names are `light`, `dark`, `emerald`, `emerald-dark`, and `midnight`. Theme scopes can nest.

## Token names

Use semantic values in component props: `background`, `card`, `subtle`, `primary`, `primaryHover`, `primaryActive`, `primaryContrast`, `muted`, `border`, and `ring`. Silva UI also exports `colorTokens`, `darkColorTokens`, `lightColors`, `darkColors`, and `themeColors` for custom themes.

## Custom themes with `createTheme`

`createTheme` is Vanilla Extract’s build-time API. It creates a CSS class with the same variable contract as Silva UI. Add that class to a normal wrapper around components. They inherit its token values automatically.

### 1. Add Vanilla Extract

```bash
npm install @vanilla-extract/css
npm install -D @vanilla-extract/vite-plugin
```

```ts vite.config.ts
import { defineConfig } from "vite"
import { vanillaExtractPlugin } from "@vanilla-extract/vite-plugin"

export default defineConfig({
  plugins: [vanillaExtractPlugin()],
})
```

### 2. Create the theme in a CSS module

Use a `*.css.ts` file so Vanilla Extract can compile it. Spreading the Silva UI exports fills the complete token contract, then your semantic overrides define the brand.

```ts src/brand-theme.css.ts
import { createTheme } from "@vanilla-extract/css"
import { colorTokens, lightColors, themeColors } from "silva-ui"

export const brandTheme = createTheme(themeColors, {
  ...colorTokens,
  ...lightColors,
  primary: "#7c3aed",
  primaryHover: "#6d28d9",
  primaryActive: "#5b21b6",
  primaryContrast: "#ffffff",
  background: "#fbfaff",
  card: "#ffffff",
  subtle: "#f3f0ff",
  muted: "#6b6580",
  border: "#ded7f5",
  ring: "#7c3aed",
})
```

### 3. Use it with Silva UI components

```tsx
import "silva-ui/style.css"
import { Button, Card, Paragraph, YStack } from "silva-ui"
import { brandTheme } from "./brand-theme.css"

export function PricingCard() {
  return (
    <div class={brandTheme}>
      <Card bg="card" borderColor="border" bordered p="large">
        <YStack gap="medium">
          <Paragraph color="muted">A custom semantic palette.</Paragraph>
          <Button>Choose plan</Button>
        </YStack>
      </Card>
    </div>
  )
}
```

The wrapper class provides `primary`, `card`, `border`, and the other variables. Any nested Silva UI component resolves them from that wrapper. You can put the wrapper inside a built-in `Theme` or make it the outer application scope.

### Dark custom theme

Start a dark version from the dark defaults.

```ts src/brand-dark-theme.css.ts
import { createTheme } from "@vanilla-extract/css"
import { darkColorTokens, darkColors, themeColors } from "silva-ui"

export const brandDarkTheme = createTheme(themeColors, {
  ...darkColorTokens,
  ...darkColors,
  primary: "#a78bfa",
  primaryHover: "#c4b5fd",
  primaryActive: "#8b5cf6",
  primaryContrast: "#1b102e",
  background: "#120b20",
  card: "#1d122d",
  subtle: "#291a3d",
  muted: "#c7bbd9",
  border: "#45315f",
  ring: "#a78bfa",
})
```

## `createThemes` versus `createTheme`

`createThemes` generates plain palette/template value records. It does not emit a CSS class. Use it when generating values, then pass the final record through `createTheme` before applying it to a wrapper. For most apps, start with `themeColors` so custom and built-in themes use the same variable names.
